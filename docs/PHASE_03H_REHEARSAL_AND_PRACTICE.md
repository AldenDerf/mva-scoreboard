## Practice scoring implementation

`lib/scoring/practice.ts` is a pure state transition module. It validates two distinct team names, format, and first serve; scores each rally for A or B; moves serve to the rally winner; recognizes regular sets at 25 and deciding sets at 15 with a two-point lead and no cap; locks a won set until explicit confirmation; alternates opening serve between sets; and completes a best-of-3 or best-of-5 match at the required confirmed set wins. Commands carry an ID and expected revision. Duplicate same-intent IDs replay without an extra point; mismatched or stale transitions fail. Undo appends a correction event and restores the last uncorrected rally's points and serve, including before set confirmation. It cannot cross a confirmed set or completed match. This module is intentionally separate from persistence and server authorization.

`/dev/practice` offers fictional team setup, large point controls, last-point correction with confirmation, visible set history/serve, set confirmation, reset confirmation, and an embedded scorebug using the existing overlay visual. Buttons are keyboard operable and have visible focus styles. The parent development layout returned 404 from a local production build. The page state is React memory in one tab: refresh clears it; another browser and OBS cannot see it. No production mutation endpoint or database connection was added. The existing protected application remains fail closed at `ACCESS_PENDING`. The separate `/dev/overlay` still renders static sample data on a transparent page; it is not realtime.

The future overlay boundary should read a broadcast-safe server snapshot (`public_id`, names/logo references, set scores, current set, serve, status, revision) at initial load and after reconnect. Realtime can signal a revision change but must trigger a fresh authoritative read. The public route remains read-only and must not contain credentials. Practice state is not a source for that route. Long names truncate, missing logos use initials, and the existing CSS scales the scorebug at large capture widths. Actual 1920×1080/1280×720 OBS capture and playback-size checks remain open.

## Online beta readiness

Read-only Vercel account inspection found an `mva` Next.js project with a READY production deployment and the existing custom domain. No `mva-scoreboard` project was listed, and neither local checkout has a `.vercel` link. The two local applications use Supabase SSR code; existing project documents say the configured Auth issuer is MVA's production Supabase project. No live Supabase dashboard, production database schema, production scoreboard grants, or Vercel environment values were inspected or changed.

**Thursday online scorekeeper plus OBS beta is not ready.** Blocking work, in the shortest safe sequence:

1. Owner confirms the intended production Supabase project/database and approves a reviewed, backed-up scoreboard schema migration there. Local `mva_dev` is not a remote backend.
2. Review and approve production-specific runtime roles, RLS/function design, network connection path from Vercel, and server-only credential provisioning. The local rehearsal guards cannot be reused unchanged in production.
3. Privately verify the first ADMIN Auth UUID, approve and execute an audited production ADMIN bootstrap, then remove its one-time function. Add SCOREKEEPER grants and assignment policy before scorekeeper access.
4. Implement server-authoritative match creation and transactional scoring persistence, event history, idempotency, correction, and role/assignment checks; connect the UI to that service. The practice reducer is a rules prototype, not persistence.
5. Implement a broadcast-safe public overlay route with authoritative initial/refetch snapshots and reconnect behavior; then provision a separate scoreboard Vercel project and preview environment.
6. Test the full flow on two machines, including mobile controls, reconnect, long names, missing logos, transparency and resizing in actual OBS Browser Source. Only then decide whether to use it for orientation.

The narrow MVA tournament/team integration, production-grade administration UI, and richer animations can be deferred for a fictional-data orientation if the owner approves that scope. Shared persistent scoring, access control, deployment, and a public synchronized overlay cannot be deferred for an online scorekeeper/OBS beta. No production action was taken.
