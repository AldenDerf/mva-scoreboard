# MVA Live Scoreboard implementation plan

**Current phase:** 03I Practice Correction Controls. **Product status:** In Development. Phase 03G SQL was rehearsed in disposable clusters; `mva_dev` and production were unchanged. The development-only practice scorekeeper supports point, serve and constrained set-history corrections in one browser tab, but online persistence and OBS synchronization are not implemented. See [Phase 03H report](PHASE_03H_REHEARSAL_AND_PRACTICE.md).

## Sequence and gates

Do not start schema or Auth work until the MVA identity boundary and scoreboard project isolation are reviewed. Do not start MVA integration until its actual schema, eligibility policy, and restricted read contract are confirmed. Do not ship score mutations before atomicity, idempotency, correction semantics, and authorization are tested. Do not call the overlay broadcast-ready before real OBS testing.

## Immediate architectural blockers

- Local `mva_dev` is PostgreSQL 18 without `auth` schema. The owner confirms that the shared configured Supabase project is MVA's production Auth project, with Site URL `http://localhost:3000` and no additional Redirect URLs. The password-only scoreboard MVP needs no callback; reserve local port 3001. Deployed MVA issuer comparison and localhost cookie/session behavior still need review. See the [Auth redirect decision](ARCHITECTURE.md#owner-auth-redirect-decision).
- MVA schema and `VERIFIED` filtering are verified in source. Proposed scheduling statuses and a restricted catalog endpoint need MVA owner approval and implementation.
- The local target is identifiable and backup/restore procedure was tested, but a current retained recovery point, owner approval of the shared target and exact checksum, non-superuser runtime credential, and production rollout approval remain outstanding.
- Proposed best-of-three and operational scoring defaults need MVA association approval; official FIVB rules are identified separately in the architecture review.

**Next bounded task:** Follow the [Phase 03H online beta blockers](PHASE_03H_REHEARSAL_AND_PRACTICE.md#online-beta-readiness): owner-review the production Supabase target and recovery plan, then prepare a production-specific scoreboard schema/runtime authorization change for explicit approval. In parallel, design server-authoritative match and scoring transactions. The local practice page can be used for rules orientation only; it is not shared with OBS. Do not rerun the local foundation migration.

## Phase 02A UI scope

The public root shows a non-operational login form with visible validation, password visibility, preview loading/error states, and an explicit notice that credentials are not sent. `/dev` contains a responsive admin shell with six real preview destinations, empty states, and a fictional dependent-selection match setup. `/dev/overlay` is a transparent, non-live scorebug sample with no controls or realtime connection. A server-side development guard returns 404 for these routes in a production start. Real dashboard URLs, matches, Auth, MVA catalog access, and OBS integration remain unimplemented.

The official Vercel `geist` package (SIL Open Font License) replaces build-time Google Fonts fetches while preserving the Geist families. The build now succeeds locally.

## Phase 02B verification

Headless Chrome rendered login, dashboard, match setup, and overlay at 360, 390, 768, 1280, and 1920 CSS pixels. No page-level horizontal overflow was measured. Email and password labels and required attributes, password visibility toggle, visible keyboard focus outline, mobile scrolling navigation, dependent division/team options, exclusion of Team A from Team B, and downstream reset after division change were inspected. The overlay reported a transparent body and no scrolling; a synthetic long name truncated within the scorebug, and initials remained visible as logo placeholders. The 710px graphic was readable at 1280×720 but too small when a 1920×1080 frame was reduced to 640px. At 1536px and above, the preview now uses a 960px scorebug with larger primary type. The Next.js development indicator was removed so it cannot appear over the preview.

OBS is not installed here, so transparency compositing, position, resize, refresh, and Facebook playback readability still need an actual Browser Source test. Use a 1920×1080 OBS canvas and Browser Source set to 1920×1080 pointed to the local development `/dev/overlay` route. Place a video or colored source behind it; confirm the space outside the scorebug is transparent, no scrollbar or framework badge appears, and the scorebug stays bottom-left after refresh. Repeat with a 1280×720 Browser Source and inspect the OBS preview and a 640px-wide recording or stream playback for names, points, sets, serve, and the “Preview · Not live” label. Test a long team name and missing logo placeholder before considering a real overlay broadcast-ready. This preview has no realtime data, so realtime/refresh correctness remains part of Phase 05.
